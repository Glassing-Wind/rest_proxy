Question: Find the implementation of symbol-context lookup and explain its graph and source fallbacks.

The implementation is **`get_symbol_context()`**, registered as a tool in [core.py:1065](/Users/michaelmarler/Projects/rest_proxy/tools/brain/code_intel/core.py:1065). Its flow is **graph lookup → candidate selection → optional local source → stored source fallback**.

- **Graph lookup:** `SYMBOL_CONTEXT_CYPHER` matches an exact symbol name or qualified name within the project, optionally filtering by file path and signature substring. It retrieves the containing file, incoming and outgoing `CALLS` **or** `CALLS_INFERRED` edges, and separate external-symbol calls. These edge types are queried together, rather than retrying inferred edges only when exact edges are absent. Results are capped at 12 candidates and 10 entries per relationship collection. [symbol_graph.py:35](/Users/michaelmarler/Projects/rest_proxy/tools/brain/code_intel/symbol_graph.py:35)

- **Candidate selection:** Results are ranked and deduplicated using file/signature matches, qualified name, source roles, symbol kind, and graph connectivity. Certain ambiguous short names return a candidate list recommending further disambiguation; otherwise the highest-ranked candidate wins. [symbol_graph.py:381](/Users/michaelmarler/Projects/rest_proxy/tools/brain/code_intel/symbol_graph.py:381), [symbol_graph.py:453](/Users/michaelmarler/Projects/rest_proxy/tools/brain/code_intel/symbol_graph.py:453)

- **Graph failure does not trigger source-only lookup.** A missing symbol returns “not found” immediately. An unavailable driver raises, and the outer handler returns an error string. Local files and stored chunks are reached only after graph resolution succeeds. The graph initialization supports configured embedded Kùzu as an alternative backend, not an automatic outage fallback. [core.py:1139](/Users/michaelmarler/Projects/rest_proxy/tools/brain/code_intel/core.py:1139), [core.py:1233](/Users/michaelmarler/Projects/rest_proxy/tools/brain/code_intel/core.py:1233), [graph_bootstrap.py:438](/Users/michaelmarler/Projects/rest_proxy/graph_bootstrap.py:438), [graph_bootstrap.py:287](/Users/michaelmarler/Projects/rest_proxy/graph_bootstrap.py:287)

- **Local source first:** With previews enabled, it joins the workspace path to the graph record’s filepath and reads from the indexed start line. Defaults are 80 lines/4,000 characters; hard maxima are 400/16,000. `full_source_preview=True` additionally respects the indexed end line within those caps. A successful local snippet returns immediately; missing, empty, or unreadable source falls through. [core.py:1093](/Users/michaelmarler/Projects/rest_proxy/tools/brain/code_intel/core.py:1093), [core.py:1144](/Users/michaelmarler/Projects/rest_proxy/tools/brain/code_intel/core.py:1144)

- **Stored source fallback:** It queries `codebase_embeddings` through the memory store’s PostgreSQL interface, restricted to the same project and file. It prefers chunks declaring the symbol, then definition chunks, then proximity to its start line, then chunk index. This is metadata-ranked retrieval, not semantic similarity search. Only the character cap is applied here; the line cap and full-span option are not applied. Exceptions are swallowed, leaving graph context without source. [core.py:1185](/Users/michaelmarler/Projects/rest_proxy/tools/brain/code_intel/core.py:1185)

For Python symbols with no displayed callers or callees, the formatter recommends `find_references` or `search_codebase`; it **does not invoke them automatically**. [symbol_graph.py:992](/Users/michaelmarler/Projects/rest_proxy/tools/brain/code_intel/symbol_graph.py:992)

**Uncertainty:** This was source inspection only. Index freshness, backend availability, and actual graph coverage remain unverified. Local previews use indexed line coordinates, so changed files can produce misaligned snippets; the stored fallback can return a nearby chunk rather than the exact symbol body.
