Question: Trace how a symbol definition and its consumers are selected across indexed projects.

The cross-project path is `trace_symbol_cross_project` → `memory.cross_project_trace.trace_symbol_cross_project_core`. It selects **one source definition**, then retrieves **structural callers and text references in a specified target project**. It does not automatically discover every consuming project. [Tool entry point](/Users/michaelmarler/Projects/rest_proxy/tools/brain/search/cross_project.py:20)

1. **Resolve the two project scopes.**  
   The caller supplies `symbol_name`, `source_workspace`, and `target_workspace`. Each workspace resolves through the registry: explicit logical mapping, matching canonical path, then indexed-project matching by path or a unique basename. If unresolved, `get_project_id` hashes the canonical path into a 12-character MD5 identifier. The core keeps separate source and target IDs. [Registry resolution](/Users/michaelmarler/Projects/rest_proxy/_helpers.py:106), [indexed-project matching](/Users/michaelmarler/Projects/rest_proxy/_helpers.py:20), [hash fallback](/Users/michaelmarler/Projects/rest_proxy/_helpers.py:144), [core scoping](/Users/michaelmarler/Projects/rest_proxy/memory/cross_project_trace.py:177)

2. **Collect and choose the source definition.**  
   The first graph query matches an exact `name` within the source project across function/type-like labels, taking at most 12 candidates. A second query finds up to 12 `EXPORTS_SYMBOL_AS` aliases whose alias name matches, returning the exporting file and target name. [Definition queries](/Users/michaelmarler/Projects/rest_proxy/memory/cross_project_trace.py:190)

   Selection uses `max(..., key=_definition_rank)`. Recognized implementation extensions get +20; stub extensions get −50; export aliases get −10. Semantic file roles penalize tests/examples/benchmarks and documentation/support files; path heuristics substitute when roles are absent. Initializer files receive additional penalties. Ties prefer an earlier start line, then a lexicographically greater filepath. There is no ambiguity prompt or file/signature selector in this cross-project API. If the winner is an alias, its target name is added to the original search name. [Ranking](/Users/michaelmarler/Projects/rest_proxy/memory/cross_project_trace.py:48), [winner and alias expansion](/Users/michaelmarler/Projects/rest_proxy/memory/cross_project_trace.py:230)

3. **Select structural consumers.**  
   The next query finds source-project nodes whose names match the original name or selected alias target, then follows incoming `CALLS` or `CALLS_INFERRED` edges from target-project callers. Results are distinct caller records, ordered by filepath and line, capped at 20. [Consumer query](/Users/michaelmarler/Projects/rest_proxy/memory/cross_project_trace.py:237)

   **This lookup is name-based, not tied to the selected definition’s node identity or filepath.** Consequently, callers of multiple same-named source symbols can appear beneath one displayed definition. Also, `Enum` is eligible for definition selection but absent from this consumer query’s target-label list. Direct and inferred calls are combined without displaying which edge produced each hit.

4. **Select text consumers independently.**  
   The core embeds the resolved names and searches target-project chunks using three candidate sets: up to 200 case-insensitive substring matches assigned score `1000`, up to 40 vector-ranked chunks, and up to 40 keyword-ranked matches. The semantic branch combines reciprocal ranks, but still requires the original or alias name to occur through `ILIKE`. The combined result is capped at 200 and deduplicated by filepath/chunk index. Thus, this is not unrestricted conceptual similarity search. [Retrieval and deduplication](/Users/michaelmarler/Projects/rest_proxy/memory/cross_project_trace.py:269)

   Python then ranks hits primarily by code/file-role heuristics, with retrieval score as a secondary key. It favors recognized code extensions and `src/`, `scripts/`, or `tools/` paths while penalizing stubs and supporting material. Only the highest-ranked chunk per file survives, with **five files total**, subsequently split into implementation and supporting hits. [Usage ranking](/Users/michaelmarler/Projects/rest_proxy/memory/cross_project_trace.py:115), [file selection and grouping](/Users/michaelmarler/Projects/rest_proxy/memory/cross_project_trace.py:377)

5. **Choose the suggested first inspection.**  
   Output prioritizes the first graph caller, otherwise the first implementation text hit, otherwise a supporting hit. Although it calls the first graph result the “strongest structural consumer,” that result was selected by filepath/line ordering, not a strength score. The definition preview comes from up to two source-project chunks in the chosen file, preferring name occurrence and proximity to the definition line. [Preview selection](/Users/michaelmarler/Projects/rest_proxy/memory/cross_project_trace.py:349), [inspection recommendation](/Users/michaelmarler/Projects/rest_proxy/memory/cross_project_trace.py:444)

The main uncertainties are completeness and identity: candidate limits can omit matches; the definition query limits candidates without ordering; text occurrences do not prove calls; and name-based graph lookup does not disambiguate overloads. No-hit output even says the symbol “appears to be defined” when definition lookup may also have failed. [No-hit wording](/Users/michaelmarler/Projects/rest_proxy/memory/cross_project_trace.py:484)
