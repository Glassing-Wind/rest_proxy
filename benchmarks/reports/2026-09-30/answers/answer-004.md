Question: Find the implementation of symbol-context lookup and explain its graph and source fallbacks.

The implementation is the MCP tool **`get_symbol_context()`** in [core.py:1065](/Users/michaelmarler/Projects/rest_proxy/tools/brain/code_intel/core.py:1065), with graph querying, candidate selection, and formatting in `symbol_graph.py`.

Its flow is **Neo4j symbol lookup → graph context → local source preview → PostgreSQL source fallback**.

1. **Graph lookup is required.** It resolves the workspace’s project ID, requires a Neo4j driver, and queries symbols by exact `name` or `qualified_name`. Optional file-path and signature filters narrow matches. It collects the containing file, incoming/outgoing `CALLS` **and** `CALLS_INFERRED` edges, plus outgoing `CALLS_EXTERNAL_SYMBOL` edges. These are combined in one query, rather than attempted as sequential fallbacks. Results are capped at 12 candidates and 10 entries per relationship list. [core.py:1092](/Users/michaelmarler/Projects/rest_proxy/tools/brain/code_intel/core.py:1092), [symbol_graph.py:35](/Users/michaelmarler/Projects/rest_proxy/tools/brain/code_intel/symbol_graph.py:35)

2. **Multiple matches are ranked or returned for disambiguation.** Ranking considers explicit filters, qualified names, signatures, file roles/path heuristics, symbol kind, and graph connectivity. Certain ambiguous short names produce a candidate list suggesting `list_symbol_matches`; otherwise the highest-ranked candidate wins. [symbol_graph.py:321](/Users/michaelmarler/Projects/rest_proxy/tools/brain/code_intel/symbol_graph.py:321), [symbol_graph.py:381](/Users/michaelmarler/Projects/rest_proxy/tools/brain/code_intel/symbol_graph.py:381), [symbol_graph.py:453](/Users/michaelmarler/Projects/rest_proxy/tools/brain/code_intel/symbol_graph.py:453)

3. **Missing graph evidence does not trigger source-based symbol discovery.** No matching record returns “Symbol … not found. Run index_workspace() first.” Driver/query failures return an error string; neither reaches the source fallback. With a matching symbol but no displayed callers/callees, Python receives guidance to use `find_references` or `search_codebase`—those tools are not invoked automatically. [core.py:1139](/Users/michaelmarler/Projects/rest_proxy/tools/brain/code_intel/core.py:1139), [core.py:1233](/Users/michaelmarler/Projects/rest_proxy/tools/brain/code_intel/core.py:1233), [symbol_graph.py:992](/Users/michaelmarler/Projects/rest_proxy/tools/brain/code_intel/symbol_graph.py:992)

4. **Source preview prefers the local filesystem.** If `workspace_id` exists locally, it reads the graph-selected file starting at the indexed `start_line`. Defaults are 80 lines/4,000 characters, clamped to at most 400/16,000. `full_source_preview=True` also respects indexed `end_line`, within those caps. A nonempty local snippet returns immediately; missing files, empty snippets, or exceptions allow PostgreSQL fallback. [core.py:1094](/Users/michaelmarler/Projects/rest_proxy/tools/brain/code_intel/core.py:1094), [core.py:1144](/Users/michaelmarler/Projects/rest_proxy/tools/brain/code_intel/core.py:1144)

5. **PostgreSQL supplies an indexed chunk.** It selects one `codebase_embeddings` row for the same project/file, preferring matching `declared_symbols`, then `chunk_role='definition'`, then proximity to the symbol’s start line, then chunk index. This is SQL selection, not vector search. It applies the character cap, but **not the line cap or full-span option**. Errors are swallowed, leaving graph context without source.
