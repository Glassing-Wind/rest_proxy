# ts-pack fork upgrade investigation — October 3, 2026

Recommendation: evaluate an upstream integration while retaining the working fork
pin. Upstream v1.20.0 is not a drop-in replacement for this project's parser and
native indexing dependency. The initial investigation below did not merge code or
repin the project. Subsequent candidate integration is recorded at the end; the
original fork checkout and operational dependency pin remain unchanged.

## What the fork preserves

The fork's docs/fork-boundary.md identifies ts-pack-index, Python graph finalization,
retrieval-adjacent analysis and GraphRAG-specific facts as local functionality.
Its commit inventory also includes semantic ingestion helpers, shadow publication,
call resolution/provenance, configured Neo4j database handling, route extraction,
semantic file roles, parser caching and Swift/Kotlin fidelity changes.

Upstream v1.20.0 contains no ts-pack-index directory. It moves Python packaging
from crates/ts-pack-python to packages/python, with native bindings in
crates/ts-pack-core-py. Python bindings are generated by alef. Simply retaining the
old paths during a merge does not establish functioning workspace dependencies,
exports or packaging; the generated binding boundary needs an explicit strategy.

reported 351 conflict messages, including 304 involving fixtures/smoke. Remaining

## Upgrade sequence and gates

1. Create an isolated candidate from fork HEAD, preserving the attributed Swift
   fix. Integrate the release's core/dependency changes with a deliberate Python
   binding strategy; preserve native index and semantic contracts.
2. Resolve source/API conflicts explicitly. Regenerate or adapt bindings through
   their supported generation path; do not rely on hand edits that disappear on
   regeneration. Review fixture changes against source semantics before accepting.
3. Build a fresh unstripped candidate wheel under Python 3.14; install it in an
   isolated project dependency environment. Record the exact commit and artifact.
4. Run test_ts_pack_contract.py, test_ts_pack_facts.py, Swift/route/semantic-role
   regressions, fork Rust/golden checks and project CI. Verify source identities,
   symbols, calls, semantic chunks and graph publication on controlled fixtures.
5. Run isolated indexing plus retrieval-quality checks. Compare golden evidence
   with the current pin and explain intentional changes; no operational database
   migration during candidate evaluation.
6. After acceptance, update both requirement pins together, rebuild packages and
   refresh the daemon/index through the documented runtime process. Retain the
   old artifact and dependency pin for rollback.

hard configuration preflight before indexing. Configuration precedence itself has
not been changed; add a dedicated regression and review before altering it.

than upstream `Interface`/`Impl`, preserving graph consumer contracts. Those test
expectations are explicitly adapted, not counted as unmodified upstream parity.
The remaining gaps are fixed: TypeScript/JavaScript declaration structure and

retained on matching spans. Swift protocol requirements recover nested methods.
Ten integration tests now pass, including indexing/full-analysis scope equivalence.
Core 313 and native index 144 tests still pass; default core ignored count remains 4.

Rebuilt macOS ARM64 (Python 3.14.4) and Linux ARM64 (Python 3.14.8) wheels were

the contract test now opens the parser to verify automatic hydration. Repeated
